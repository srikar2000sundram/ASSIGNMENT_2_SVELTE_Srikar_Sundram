A framework-agnostic StencilJS component library built for the **Recipe
Finder & Meal Planner** app. Compiles to standards-based Web Components,
published to npm and consumed by the [`recipe-finder-app`](https://github.com/srikar2000sundram/assignment_2_NAGP/blob/main/recipe-finder-app)
SvelteKit project — see [`../docs`](https://github.com/srikar2000sundram/assignment_2_NAGP/blob/main/docs) for the full architecture
(`architecture.md`) this library was built against.

## Components

| Tag | Purpose |
|---|---|
| `<recipe-ui-card>` | Recipe summary card (discovery grid, favorites, meal-plan picker) |
| `<recipe-ui-search-bar>` | Debounced search input |
| `<recipe-ui-filter-chip-group>` | Multi-select filter chips (category / cuisine / ingredient) |
| `<recipe-ui-rating-badge>` | Small colored label/tag |
| `<recipe-ui-form>` | Create/edit form for user recipes |
| `<recipe-ui-meal-slot>` | One day's cell in the weekly meal-plan grid (assign, change, remove) |
| `<recipe-ui-modal-dialog>` | Modal shell (body + `footer` slot) |

Full prop/event/slot contracts: [`../docs/architecture.md`](https://github.com/srikar2000sundram/assignment_2_NAGP/blob/main/docs/architecture.md#component-contracts).
Per-component generated API docs also live alongside each component's source,
e.g. `src/components/recipe-ui-card/readme.md` (regenerated by every build).

## Design principles

These hold for every component here, and are the reason the library is
reusable rather than merely extracted:

- **Props in, events out.** No component fetches data, reads app state, or
  imports anything from a consuming app. It renders what it is given and
  emits a `CustomEvent` describing what happened.
- **No business rules.** `<recipe-ui-form>` collects a recipe and emits it;
  it does not decide what a *valid* recipe is. The host validates and feeds
  failures back through the `errors` prop.
- **Controlled where it matters.** `<recipe-ui-filter-chip-group>` emits the
  full next selection and waits for the host to feed it back via `selected`,
  keeping no internal copy that could drift out of sync.
- **Themed by inheritance, not by API.** Every colour, radius and font is
  read as `var(--ruik-*, <fallback>)`. CSS custom properties inherit through
  shadow boundaries, so a host themes all seven components — dark mode
  included — by defining those variables once, with no theme prop and no
  stylesheet to import. Each fallback keeps the component presentable
  standalone.

## Using this library

Install the published package:

```bash
npm install @srikar_sundram/recipe-ui-kit
```

**Lazy loading (recommended, used by `recipe-finder-app`)** — register all
components once, then use them as plain HTML tags anywhere:

```ts
import { defineCustomElements } from '@srikar_sundram/recipe-ui-kit/loader';

defineCustomElements();
```

```html
<recipe-ui-card recipe-id="52772" recipe-title="Teriyaki Chicken" category="Chicken">
  <!-- default slot: per-card actions -->
  <button>Edit</button>
</recipe-ui-card>
```

Note the attribute casing: `recipeId` as a **property** is `recipe-id` as an
HTML **attribute**. Object and array props (`options`, `selected`, `recipe`,
`initialValue`, `errors`) cannot be expressed as attributes at all and must
be set as properties — which is what a framework binding like Svelte's
`options={...}` does for you.

Listen for events the standard way:

```ts
document.querySelector('recipe-ui-card')
  .addEventListener('cardClick', (ev) => console.log(ev.detail.recipeId));
```

One gotcha worth knowing: content you project into `<recipe-ui-card>`'s
default slot renders *inside* the element that carries the card's own click
handler, so a click on a slotted button also fires `cardClick`. Call
`ev.stopPropagation()` in the slotted element's handler if that is not what
you want.

**Standalone / tree-shaken import** — if you only need one component:

```ts
import '@srikar_sundram/recipe-ui-kit/recipe-ui-card';
```

Types for props/events (`FilterOption`, `RecipeFormValue`, `RecipeFormErrors`,
`MealSlotRecipe`, `RatingBadgeVariant`) are exported from the package root:

```ts
import type { RecipeFormValue } from '@srikar_sundram/recipe-ui-kit';
```

## Local development

```bash
npm install
npm start       # dev server with live reload at src/index.html → :3333
npm run build   # production build → dist/ + loader/
npm test        # 73 tests (@stencil/vitest)
npm pack        # produce the publishable tarball
```

Tests run in two Vitest projects: `*.unit.test.tsx` in Stencil's mock-doc
environment for components with no browser dependency, and `*.cmp.test.tsx`
in a real headless Chromium for anything involving events, timers, slots or
shadow DOM. Details and the edge-case inventory:
[`../docs/testing.md`](https://github.com/srikar2000sundram/assignment_2_NAGP/blob/main/docs/testing.md).

## Publishing

```bash
npm version <patch|minor|major>   # also creates a git tag
npm publish                       # prepublishOnly rebuilds dist/ first
```

Add a section to [`CHANGELOG.md`](https://github.com/srikar2000sundram/assignment_2_NAGP/blob/main/recipe-ui-kit/CHANGELOG.md) before bumping. The bump
policy — a component's public API is its props, events and slots — is in
[`../docs/architecture.md`](https://github.com/srikar2000sundram/assignment_2_NAGP/blob/main/docs/architecture.md#7-versioning).
Step-by-step publish instructions:
[`../docs/RUNBOOK.md`](https://github.com/srikar2000sundram/assignment_2_NAGP/blob/main/docs/RUNBOOK.md).

Current version: **0.2.0**.
